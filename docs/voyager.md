# Принципы Voyager и их адаптация

Изучен открытый [MineDojo/Voyager](https://github.com/MineDojo/Voyager), снимок исходников `55e45a880755d0c8c66ca7fb5fe7962ac8974f89`. Это исследовательский источник идей; оригинальный бот и его зависимости не устанавливаются, его код не включён в Copilot.

| Исследовательский механизм | Исходник Voyager | Реализация Copilot |
|---|---|---|
| Automatic Curriculum: следующая задача на основе состояния, выполненных/неудачных задач | [curriculum.py](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/agents/curriculum.py) | `learning/curriculum.py`: дерево рецептов, количества, ограничения технологий, выбор доступной цели, альтернативы, предпочтения. Ollama формулирует стратегическую цель из речи |
| Skill Library: накопление успешных навыков и retrieval | [skill.py](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/agents/skill.py) | `learning/library.py`, `memory/store.py`: SQLite FTS5 unicode61 (при отсутствии FTS — поиск по загруженным SQLite-записям), процедуры для человека, источники, версии, условия, использование |
| Critic / iterative feedback: сравнение результата и задачи, исправление | [critic.py](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/agents/critic.py), [voyager.py](https://github.com/MineDojo/Voyager/blob/55e45a880755d0c8c66ca7fb5fe7962ac8974f89/voyager/voyager.py) | `instructions/verifier.py`, `learning/reflection.py`, `instructions/engine.py`: визуальный критик Ollama, точные локальные проверки интерфейсов/количеств, журнал сравнения и причин, исправление, защита от повторов |

В Voyager навыки — JavaScript-процедуры для бота с наблюдением структурированного игрового состояния и исполнением через Minecraft-адаптер. В Copilot навыки — строго типизированные человеческие инструкции. Исполнителя игрового ввода нет. Экран и явные сообщения человека — единственные игровые источники; Lua/JS/Python из библиотеки не исполняются. OpenAI embeddings/Chroma заменены SQLite-поиском, платная LLM — Ollama Qwen3-VL.

Цикл: OBSERVE (снимок) → PLAN (LLM + расчёт рецептов) → EXPLAIN (один шаг и причина) → HUMAN ACTS → VERIFY (новый снимок/ручное подтверждение) → REFLECT (сравнение, вывод, коррекция, память) → CONTINUE.

Материальный план пересчитывается перед следующим действием по актуальным подтверждённым запасам. Он не превращает завершённую задачу «показать инвентарь» в разрешение крафтить при всё ещё неизвестных ресурсах. Выполненные и отложенные пользовательские задачи сохраняются. Целевая вещь в достаточном количестве вызывает предложение ручного завершения цели и паузу.

Автоматический поиск альтернатив ограничен 128 комбинациями достижимых рецептов. Предпочтение механизма применяется к сравнимым по доступности и нехватке ресурсов вариантам. При неизвестной технологии или противоречии рецептов программа сначала получает сведения, а не придумывает доступ. Для общего невещественного задания стратегический DAG формирует локальная LLM с проверкой зависимостей и статусов.

Саморефлексия не заменяет верификацию и не может объявить успех. Причина локально классифицируется как нехватка ресурсов/расхождение рецепта/интерфейс/неизвестная; сложное сравнение и предложение исправления возвращает визуальный критик Ollama. Локальная классификация эвристическая. Неудачные проверки учитываются по семье «действие + предмет» на цель; успех посторонней задачи не сбрасывает счётчик. После лимита нужны новые исправленные данные или правка плана. Данные переживают перезапуск SQLite.

Подтверждённые процедуры накапливаются из успешных эпизодов, снабжаются условиями и идентификаторами рецептов. Человеческое подтверждение обозначено `user_report`, изображение — `verified`, предположение — `hypothesis`, противоречие — `disputed`, замена — `superseded`. Одношаговый подходящий навык можно повторно предложить непосредственно, многошаговые — использовать как контекст планирования, проверяя каждый следующий шаг. Это ограничение первой реализации, не выполнение оригинального Voyager.
